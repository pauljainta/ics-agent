# Publication and Secret Handling

This repository is a public research implementation. Use authorized, isolated testbeds and keep live deployment configuration outside tracked source.

## Sanitized Publication

The migration to `pauljainta/ics-agent` rebuilt every published branch and the existing evidence tag. Historical content was checked for credentials, private deployment coordinates, personal workstation paths, and author email addresses. Required compiled OpenPLC payloads were sanitized using Python 3.10; generated bytecode caches were removed from history.

Modeled lab addresses were consistently remapped into the special-purpose `198.18.0.0/15` benchmarking range. These are research topology values, not deployment coordinates. Source-relative paths, standard system paths, public references, and evaluator ground-truth specifications remain where needed by the implementation.

Git commit IDs changed. Clone the new repository instead of merging an older clone, which could reintroduce removed history. Any credential that was previously used in a real service should be rotated; rewriting Git does not revoke credentials or remove copies from previous repositories and clones.

History sanitization changes source bytes. The SCADAVER branch maintains its own refreshed input-integrity manifests; historical reports do not establish new results for modified sources.

## Keep Local Values Local

- Store credentials and deployment settings in ignored `.env` and `configs/private/` files.
- Use placeholders in tracked examples, and avoid personal absolute paths in code, documentation, logs, screenshots, and compiled artifacts.
- Keep model weights, experiment result bundles, and generated caches outside tracked source.
- Never include private infrastructure manifests or raw audit findings in a commit.

## Repeat the Secret Scan

With Gitleaks installed, scan all branch and tag history from a complete clone:

```bash
git fetch origin --prune --tags
gitleaks git --redact=100 --log-opts="--all --full-history" --config=.gitleaks.toml .
```

The configuration extends the scanner's default rules. Its narrow allowlist identifies the reviewed original and sanitized source-integrity SHA-256 lines by exact path, filename key, and checksum; it does not exclude the file or disable credential detection. Scanning is one layer of review, and a clean result is not a guarantee that every possible private value has been identified.

Do not paste suspected secrets into public issues. Report them to the maintainer through an available private channel.
